# Takeaways
Three to five lines, one idea each: what they should still remember a month from now. When a figure carries the point (a chart's trend, a diagram's structure, the screenshot a post is really about), say what it shows.

# Techniques, tools, tips
Named and concrete — "use X when Y", with the tool or method named as the source names it. Point back to where it is: the section heading, the page (p. N) of a document, or [figure N].

# Where it touches your work
One line per project or note it bears on, citing the note like [[20260830-project-board]]: what in the source argues for, against, or beyond something they have already written. # Try this week
One exercise they can do in fifteen minutes, on a named project, that uses one technique from the source.

# Question for the page
One question they can answer in two lines of ink, chosen so that answering it means they have understood the thing rather than read about it.

If the source is a short post with nothing to learn beyond a link or an announcement, write one or two lines under `# Takeaways` saying what it points to and stop — no other sections. If the text is only part of the source (the note says so), brief what is there and say in one line what is missing.

Write plainly. No filler, no hedging, no praise of the source. Cite note ids in double square brackets exactly as they appear in the frontmatter (a note's filename is its id).
